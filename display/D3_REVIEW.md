# Review of d3 Usage in the Display Project (June 2025)

## a) Overview of d3 Functionality Used

The `display` project leverages d3 for:

- **Force-Directed Graphs**: Rendering and simulating network graphs (nodes/edges) using `d3.forceSimulation`, `d3.forceLink`, `d3.forceManyBody`, and `d3.forceCollide`.
- **SVG Manipulation**: Creating and updating SVG elements (`g`, `circle`, `rect`, `path`, `text`, `image`) with d3's selection and data join patterns.
- **Scales**: Using `d3.scaleLinear` and `d3.scaleOrdinal` for node sizing and coloring.
- **Zoom & Pan**: Implementing zoom and pan with `d3.zoom` and custom drag handlers.
- **Geo/Map Overlays**: Displaying maps with GeoJSON and `d3.geoPath`, `d3.geoAlbers`, and fitting projections to SVG.
- **UI Controls**: Populating `<select>` and handling events with d3 selections.
- **Lifecycle Visualization**: Drawing state machines using d3 for layout and transitions.

## b) Suggestions for Bringing in Strong Typing

- **Replace `any` with Explicit Types**: Many d3 selections and data objects are typed as `any`. Define and use interfaces for nodes, links, and map features (e.g., `INode`, `IEdge`, GeoJSON types).
- **Type d3 Selections**: Use `d3.Selection<...>` generics for selections, e.g.:
  ```ts
  let node: d3.Selection<SVGCircleElement, INode, SVGGElement, unknown>;
  ```
- **Type Simulation**: Use `d3.Simulation<INode, IEdge>` instead of `any`.
- **Type Data Providers**: Ensure all data provider methods return typed objects, not `any`.
- **Type Event Handlers**: Use d3's event types for drag/zoom handlers.
- **Type Map Data**: Use GeoJSON types from `@types/geojson` for map features.
